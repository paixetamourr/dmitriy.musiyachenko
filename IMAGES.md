# Как дальше работать с изображениями

Оптимальный источник — оригинальные файлы фотографий и макеты Figma. Для текущей версии изображения уже получены из Figma; повторно присылать их не нужно.

1. **Хранить исходники отдельно.** Полноразмерные фотографии, PNG интерфейсов и исходные SVG не перезаписываются оптимизированными копиями. Загруженные для этой работы исходники сохранены в рабочей папке `work/source-images` рядом с папкой `outputs`, вне публикуемого сайта.
2. **Передавать новые фотографии файлами.** Подойдут оригиналы через облачную папку или ZIP. Если использовать мессенджер — отправлять как файл, чтобы он не уменьшал разрешение. Скриншот фотографии хуже исходного фото.
3. **Указывать место замены.** Например: «главная, обложка выставки» или «люмин, поиск стилистики, фото 3». Кадрирование лучше оставить в Figma: тогда сайт повторит выбранную композицию.
4. **Готовить несколько размеров.** Сейчас сайт использует версии шириной до 640, 1280 и 2440 px, без увеличения маленьких исходников. Браузер выбирает файл по ширине экрана и плотности пикселей. Картинки ниже первого экрана загружаются по мере приближения к ним.
5. **Проверять качество на реальном размере.** Для текущих растровых материалов используется WebP с качеством 94. Это сжатие с потерями, поэтому исходники сохранены. Если на конкретном интерфейсе видны артефакты вокруг текста или линий, для него стоит использовать lossless WebP или PNG. Фотографиям обычно достаточно качественного WebP.
6. **Логотипы и иконки сохранять в SVG.** Они остаются чёткими при масштабировании. В проекте SVG хранятся локально, а не по временным ссылкам Figma.

Перед обновлением проверяем пропорции, кадрирование, отсутствие пустых краёв, мобильную версию и размер загрузки. Уже сжатые WebP повторно не пересжимаем: новые версии всегда готовим из исходника.

После утверждения сайта можно отдельно удалить из публикуемой версии неиспользуемые старые изображения. Оригиналы при этом должны остаться в архиве.
